## Execution checkpoint

Keep `RunSimulationService` as the sole run calculation authority. Turn its existing required-room, spatial-interaction, optional-branch and floor loops into suspended in-memory execution. The continuation owns the compiler-generated loop cursors and locals, one original `RunParty`, reached effects, room/branch evidence and carried loot. It cannot be constructed, edited or serialized by callers. Inspection returns values; an expected event ordinal rejects stale callers. Durable cursors require a reviewed Phase B representation, not serialization of an iterator.

Run identity remains `run-<sequence>`; existing party, encounter, room-loot, branch-loot, branch-choice, depth-objective and floor-transition seeds remain unchanged. Capture configuration, loot tables, runtime Heat/mana/crisis, posture, geometry and pre-run knowledge before advancement. `ActiveFloorRunSnapshot` remains the canonical input authority. Compatibility route callers also receive private copies.

Boundaries: party formation, room entry, each legal tile movement, each reached/unreachable interaction, room reward calculation/completion, branch choice, each branch assignment, branch return, floor choice/transfer, terminal calculation. Preserve existing path-step/category/sequence/ordinal-ID order and required floor/room order. Event ordinals supply the within-run total order, even at equal timestamps. No Unity frame, camera or wall-clock dependency. Event batches are bounded; retaining a full new event history is unnecessary. Existing terminal diagnostic arrays remain bounded by validated input workload.

Timing is an injected typed contract: exact nonnegative integer logical units per traversed tile edge and interaction category/transition. Checked integer accumulation rejects overflow. No production movement/interaction durations exist; test timing is explicitly synthetic. Untimed manual draining uses ordinal order without claiming elapsed gameplay time, so no unapproved speed becomes a player dependency. Canonical legal room paths and saved connection geometry supply distance, including branch outward/return travel. No animation delays.

HP changes only at the existing encounter resolver call. Loot rolls occur at the existing qualified room reward or branch loot boundary. Planning paths does not roll combat, decide branches or create rewards. Room reward qualification remains unchanged. One party crosses floors without healing. Run outcome is calculated once and retrieved once; advancing terminal state is a no-op. Invalid budgets/stale cursors fail before advancement; execution failure poisons the continuation and publishes nothing. Work is never retried automatically.

Completed callers explicitly drain this same execution. Canonical manual publication still performs one detached candidate, both retained Heat stages, knowledge learning, run history/sequence and eligible objectives, then one atomic persistence/readback. No partial saves, schema change or migration. Resuming an in-memory execution does not grant authority to publish over newer canonical state. Phase B must order settlements against current Heat/knowledge, reapply resolved deltas rather than starting-state overwrites, merge learning under applicability rules and guard duplicate RunIds in the canonical transaction. Concurrency is not activated here.

## Pure boundary calculations

Heat queries validate the configured zero-minimum finite domain and use inclusive lower/exclusive next-lower membership. A restricted upper boundary uses the immediately preceding IEEE-754 binary64 value, never epsilon or integer rounding. Apply already-resolved eligible deltas separately in stage order and report applied/discarded signed deltas. No offline run settlement or new Heat formula. Legacy diagnostic tier maxima retain compatibility; the pure boundary contract derives continuous endpoints from next-tier minima.

Historical mana captures the accepted interval-start wallet, capacity and canonical resolved rate/efficiency. Historical queries reuse the offline grant calculation, issue no grant and do not mutate a save. No time cap, ticks or second wallet. Permanent interval retention/admissions belong to Phase B.

## Implemented interface and continuation details

`StartSnapshot(sequence, immutableSnapshot, timing?, eventLimit?)` is the canonical start interface. `StartRoute` captures compatibility/synthetic route inputs defensively. The returned `RunExecution` is an opaque continuation handle. `Inspect` copies member HP values and exposes the last boundary, next ordinal, logical time, carried loot and reached interaction counts. `Advance(eventBudget, expectedNextOrdinal)` returns only the observed batch; `AdvanceToNextEvent` is its single-boundary convenience. Keep the same handle to resume. `TakeOutcome` is available once after Terminal; `DrainToCompletion` advances the same core without allocating an observation batch for each event. Existing completed entry points drain that core.

The suspended required-room loop owns floor/room cursors, original party, room seeds, reached effects, generated-item lists and counters, survivor counts and terminal accumulators. The nested spatial loop owns path step and interaction cursor; the branch loop owns approach/outward/return cursors, decision and per-assignment consequences. No caller can write or reconstruct these cursors. Stale ordinals, invalid budgets, cursor corruption, timing overflow and total-work exhaustion cannot produce an outcome. A technical advancement failure invalidates the handle; it is not a retreat or an automatic retry.

`RunStep` carries immutable identity/order, logical timestamp, kind, assignment/room/floor identity, coordinate space, traversed distance, chosen continuation, exact encounter HP evidence and carried loot after the boundary. Room-local coordinates remain in the existing intraroom basis; connections/corridor positions use canonical floor coordinates. Saved socket rotation comes from the existing structural connection authority. Branch choice follows legal travel to its socket; the approach reverses on skip, and entered corridors return exactly once. Completed-room approach/return movement is a control-flow transition, not another room visit or a second content-effects pass. Required-room loot interactions establish reached evidence; the existing qualified room-reward roll remains at RoomComplete. Branch loot rolls remain per reached branch assignment.

Ordering is the original required floor/room order. Room interaction ties use path step, monster/trap/loot rank, assignment Sequence and ordinal AssignmentId. Branch assignments retain their separate existing distance-from-source, Sequence and ordinal AssignmentId order; no category priority is added there. Room completion precedes branch processing and floor decision/transfer. RunId plus zero-based event ordinal identifies every emitted boundary. Equal logical timestamps keep this ordinal order; no new cross-party scheduling priority is selected.

Budgets count event boundaries. Timing uses whole-boundary checked integer durations, including monster movement distance. This interface does not implement an accepted-interval deadline gate or next-event due-time scheduler. Phase B must add those and an explicit durable cursor representation within this same authority before offline admissions/catch-up. Serial in-memory execution here is not durable-party or concurrent settlement qualification.

The canonical start path consumes existing validated spatial/configuration workload envelopes. A conservative total-event ceiling is derived from bounded path/interaction/connection cardinalities; callers can request a lower ceiling, never enlarge it. Startup copies and validates/plans inputs, including future legal paths; it does not execute future combat, branch choices or rewards. First advancement also calculates static configured-route aggregates. Advancement retains the current room plan and reached diagnostics; it does not build a second event history. Existing BFS/path-planning and aggregate resolver costs remain bounded by those envelopes, with no per-frame pathfinding or serialization. Compatibility array callers remain intended for existing routes/tests, not unbounded external streaming inputs.

Pure Heat results cover the active zero-minimum configuration profile and reject negative-profile activation. Historical mana intervals freeze the existing canonical resolved rate, start wallet, capacity, configured/effective efficiency and accepted timestamp bounds. Queries allow both interval endpoints and return non-persistable calculation evidence. Their formula is the same extracted calculation used by the existing actual offline grant; no scheduler or extra grant invokes them.
