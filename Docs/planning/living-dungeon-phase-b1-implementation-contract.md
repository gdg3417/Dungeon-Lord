## Choice and authority

An explicit durable state-machine cursor would need to externalize the required-room, spatial interaction, branch approach/return, floor and aggregate resolver locals. It offers direct restoration but replaces substantial proven control flow and broadens this packet. Choose detached deterministic replay of a validated committed prefix instead. Recreate a fresh iterator using complete retained start inputs, replay only the committed ordinal count, and independently compare the rolling event/consequence digest and boundary inspection. Never serialize an iterator, compiler-generated locals, arbitrary object graphs or reflection-derived state. No second simulator, writable event journal or canonical publication is introduced.

Replay is O(committed events plus original input planning/resolver work), memory O(captured inputs, reached diagnostics, current plans). An injected checkpoint byte limit and replay-event limit reject unacceptable work before reconstruction. The existing input-derived total-event bound remains. This is bounded restoration, not multi-month catch-up or a device responsiveness guarantee.

## Retained inputs, evidence and compatibility

Retain configuration and loot capture, table identity, runtime Heat/mana/crisis, start tick, sequence/posture, immutable required and optional plans, geometry/connections, branch and floor knowledge/fingerprints, timing and execution ceiling. Retain compatibility null discriminators explicitly. Start payload digest must match an independently supplied expected identity, ultimately owned by a canonical transaction; a self-provided checksum is not authenticity. RunId/seeds and AssignmentId/order remain unchanged. Decode into new data and a new engine; no live dungeon/content reference is substituted.

Checkpoint format identifies its contract and executable rules, start payload, next ordinal, logical time, accepted deadline, active/terminal state and consumed-outcome flag, rolling committed event digest and exact member HP/carried loot/reach evidence. Prefix digest binds identities, order, time, encounters and consequences; replay reconstructs the private reached effects, generated item lineage, branch state and floor cursor from the pinned inputs. No finished run record or parallel event history is stored. Export returns isolated bytes, never mutable live references. Restoration additionally requires the independently retained complete checkpoint identity, protecting consumed-outcome/deadline metadata and the accepted prefix itself. Computing expected identities from untrusted incoming bytes is not authentication.

Only this B1 executable rule implementation is supported. A string/hash/config snapshot cannot supply old executable semantics. Any future resolver/control-flow change must explicitly preserve and requalify this implementation or change its identity and reject old checkpoints. No historical registry is invented. Unsupported rules, malformed/noncanonical/truncated bytes, mismatched start identity, impossible ordinal, mismatched replay evidence or unsupported failed handles fail closed with stable technical reason codes. Failed restore exposes no partial execution and writes nothing. Checkpoint export rejects poisoned handles; terminal retrieval consumption survives restoration.

## Pre-effect boundary and logical time

Integrate a two-stage internal boundary protocol into the existing iterator path: announce kind and geometry distance before resolver effects, then resume that same path to commit and emit its exact result. The announcement never resolves an encounter, branch, reward or floor choice. Verify the committed kind/distance matches its announcement. Pure movement uses the same protocol. No predictive resolver, speculative execution or rollback.

Timing is immutable, injected integer logical units relative to run start at zero. Each boundary is due at committed elapsed time plus checked distance × units/edge plus that category's interaction duration. Monster approach distance is included; floor transfer uses its configured duration. Consequences commit at completion of this whole boundary; no new start-event gameplay is introduced. A first zero-distance entry is due at zero; canonical entrance-connection movement can instead precede room entry and is timed by its traversed edges. Terminal, choice, completion and other zero-duration events use current elapsed time and canonical ordinal order. Eligibility is inclusive (`due <= deadline`). Event budget limits equal-time/zero-duration work. A cached announcement survives budget/deadline stops without losing an event. A deadline must be nonnegative and at least the last accepted deadline and current elapsed time. Overflow fails before event effects and poisons the handle. Untimed manual completion retains original event ordering/formulas with no production timing.

## Implemented format and API

`StartSnapshot` and `StartRoute` capture complete inputs. `RunExecution.ExportCheckpoint(limits)` returns immutable `RunCheckpoint` metadata and copied `GetBytes()` output. `RunSimulationService.RestoreCheckpoint(bytes, expectedCheckpointIdentity, expectedStartIdentity, expectedOrdinal, limits)` returns either a wholly validated fresh execution or a stable failure reason with no execution. Neither API has a canonical file system, save session or settlement callback. Aggregate-only `SimulateOnce` remains an internal untimed drain without a public checkpoint handle.

Format 1 is a fixed field sequence, little-endian signed 32/64-bit integers and binary64 where used in evidence. Boolean bytes must be exactly 0 or 1. Blobs use a signed 32-bit byte count; nullable strings alone allow -1. Strings use strict UTF-8 without BOM. Counts are checked against remaining bytes before allocation. No trailing bytes are accepted. The payload ends with a raw 32-byte SHA-256 checksum; the external complete identity is lowercase hexadecimal SHA-256 of all checkpoint bytes, including that checksum.

Payload order:

1. Int32 format, string executable identity `run.executable.living-dungeon-b1.v1`, blob start inputs.
2. Int64 next ordinal, elapsed logical units and accepted deadline (-1 means no timed deadline accepted).
3. Boolean terminal and consumed-outcome flags; blob rolling 32-byte committed-prefix digest; blob boundary inspection.
4. Raw 32-byte payload checksum.

Start inputs contain format, sequence, tick, effective event ceiling, posture, captured configuration JSON and explicit absent composition/PhaseSix flags, nullable captured loot JSON/table, captured runtime JSON, optional five-field immutable timing, then either retained snapshot values or captured compatibility rooms with explicit null Spatial/Assignments flags. Snapshot values contain original configuration/loot/branch knowledge/floor knowledge/runtime JSON, posture/table/tick and ordered floors. Each floor retains ID/index/knowledge fingerprint, plan/spatial/connection JSON and connection work bound. The JSON is explicit existing typed input data, never an iterator or arbitrary graph; reconstruction must recapture byte-identically. Historical executable/serializer differences that cannot meet this contract are unsupported.

Inspection encoding includes RunId, next ordinal, time, timing/terminal flags, carried value, encounter/loot counts and ordered member ordinal/class/current/max HP. The rolling digest starts at SHA-256(start inputs), then folds each committed event's full identity/order/time/kind/geometry/distance/choice/carry, exact encounter rule/member/damage/HP/severity/expertise evidence and resulting inspection. Derived private locals are replayed, never imported as independently writable state. Item identities, branch/floor reasoning and reached aggregates are derived under the qualified executable and checked by full structured equivalence tests. Terminal outcome records are not retained in the checkpoint.

Caller-injected `RunCheckpointLimits` bounds total bytes and replay events; no production default is selected. Source size and committed-prefix workload are rejected before JSON reconstruction/replay. Event advancement retains Phase A's input-derived ceiling; internal announcements do not count as extra gameplay events. Encoding/decoding and start capture use O(byte length) temporary storage; replay uses O(committed-prefix diagnostics plus input/current plans). Each event adds bounded party-inspection/hash work. Existing per-room BFS and resolvers remain; no allocation-free or constant-time restore claim.

`NextDueTime()` may prepare/cache the next pure announcement. `AdvanceThrough(deadline, eventBudget, expectedOrdinal)` accepts nondecreasing inclusive deadlines. Preparing may compute pure paths/static aggregates and iterator control locals, but does not resolve future encounters/rewards/choices or publish anything. Announcements are derived and omitted from checkpoints; replay regenerates the next announcement on demand. This preserves a checkpoint taken after an ineligible peek. Whole-boundary completion time is immutable movement distance times units per edge plus configured interaction/transfer units. Equal times retain ordinals; a finite budget bounds zero-duration events. `Advance`/manual drain explicitly authorize ordinal progression regardless of timing. If a deadline has been accepted, later ordinal commits raise its recorded lower bound to at least committed elapsed time, so mixed API usage stays reconstructible and cannot accept a later deadline below either bound. This does not introduce wall-clock authority. A future deadline-governed scheduler must exclusively use the deadline API for its progression.

Argument failures leave progression usable; workload/cursor/time failures poison the handle with `run.execution.failed`, disable export/outcome access and dispose the iterator. Failed restore disposes any private candidate. Export never legitimizes a poisoned run. Complete checkpoint identity, start identity and expected ordinal must ultimately come from the reviewed canonical committed transaction, not the checkpoint's own claims. B1 provides no durable freshness/authenticity owner; B2/B3 must add that transaction authority and duplicate-safe economic settlement together.

Supported executable boundary: this qualified B1 resolver/control-flow implementation on the tested Unity 6000.3.2f1 Windows host/player. The identifier selects behavior that actually exists here; it cannot preserve historical semantics on its own. Any future gameplay/resolver/serialization change must preserve and requalify this implementation or bump executable/format identity and reject it. No arbitrary cross-version/platform restoration or automatic rules upgrade is qualified.
