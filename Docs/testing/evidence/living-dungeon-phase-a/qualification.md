## Implemented behavior

`RunSimulationService` remains the only run calculation authority. Its existing loops suspend through `RunExecution`: one original party, immutable copied inputs, actual legal paths, evolving HP, reached effects, generated/carried loot, branch decisions and floor transitions. Advancement emits only the reached event batch. It does not populate an already-completed outcome or resolve future gameplay for presentation.

The continuation privately retains compiler-generated loop cursors/locals. Inspection copies member health and exposes identity, ordinal, time, last boundary, encounter/loot counts and carried value. Each step identifies its kind, geometry coordinate space, assignment, distance, chosen continuation, exact HP encounter evidence and carried loot after the boundary. `Advance` validates a caller's expected ordinal and event budget. A derived finite total-event ceiling and checked integer time prevent cursor/work/time failure from producing an outcome. Failure invalidates the handle without publishing gameplay. Terminal outcome retrieval is allowed once.

Existing `SimulateRoute`, `SimulateOnce`, `SimulateSnapshot`, and canonical manual run calculation drain this same core. The established detached candidate still owns both foreground Heat stages, learning, history/sequence and eligible objectives, followed by one atomic persistence/readback/publication. No partially advanced manual run is saved.

Room path and interaction ordering are unchanged. Required physical connections reuse saved socket/footprint authority; branch approach reaches its actual socket before choice, reverses on skip, and entered corridors return once. Completed-room approach/return remains control-flow movement rather than a second room/content visit. Room-loot interaction records reached evidence; the qualified reward roll remains at RoomComplete. Branch loot rolls at its reached assignment. One party crosses floors without healing/refill/replacement. New event ordinals do not alter old terminal encounter/spatial/branch/floor evidence.

## Pure Heat and mana

`RunHeatBoundaryCalculation` consumes resolved deltas, validates the active zero-minimum profile/current domain and preserves fractional membership. Lower thresholds are inclusive, next-tier minima exclusive and final maximum inclusive. A restricted ceiling is the immediately preceding IEEE-754 binary64 value. It uses no epsilon or integer rounding. First/second stages apply separately in order and expose requested/applied/discarded signed deltas and stable reason/tier/source evidence. Tests cover both threshold directions, representable ceilings, last-tier maximum, stage order, foreground equivalence, invalid/nonfinite values and overflow. It is not wired to offline run settlement or normal foreground formulas.

Historical mana freezes accepted interval-start wallet, capacity, canonical resolved rate and base/effective efficiency. Queries at several timestamps, including endpoints/capacity crossing, reuse the existing actual offline grant calculation and return `PersistenceRequired = false`. The saved/runtime state is unchanged. The existing configured 15% efficiency, fractional precision, no eligible duration cap, one actual capacity-clamped grant and absence of online-tick replay/second wallet remain. Actual offline lifecycle/persistence tests remain in the full regressions.

No mixed-period settlement is activated. Required causal inputs are encounter ordinal/time, member HP death cause, posture/configuration, reached source placement and reward/extraction lineage. Elite Heat stays zero because no actual elite-death source exists. Unresolved terms: multiple-death bonus period ownership, full-party survivor cooling qualification, extraction rounding/clamps and survivor ratio over carried loot, both cooling caps, posture offset and sequential composition/casualty clamp saturation. The existing formulas do not define period ownership for them. No proportional allocation or completion-time classification is invented.
