## Implementation

- The map's only layout child is the full-width viewport. Floor navigation is an absolute overlay drawn after it, inside the safe area, with no opaque rail background. The rail, ScrollView and empty descendants ignore picking; actual floor/toggle buttons and visible scroll controls intercept input. The existing panel-raycast exclusion and sole camera/viewport remain authoritative for presentation. Collapse reduces occlusion without moving/resizing the camera. Floor identity, descending ordering, lifecycle and draft indicators are unchanged.
- Fifteen nonempty imported masonry masks now use a wider dark inset and raised light cap. Individual resolved room **and fixed-structure** footprints retain their own perimeter. Physical contact alone does not open a seam. Saved edge projection reuses the existing unique socket/geometry adapter, including its returned local socket offsets; optional branches reuse their existing geometry validator. Exact transformed socket positions/facing supply openings and noninteractive threshold frames. Direct doorways use one frame; physical corridors use endpoint transitions. The frames are pooled and ordered by stable saved edge identity. Removed/invalid edges lose their frames. Selected masks keep the same openings and frames draw above them.
- Two original offline Pillow PNGs (`doorway-threshold`, `corridor-threshold`) provide open jambs and paving marks, without a closed door, lock, label, collision or traversal state. Unity authored/imported their metadata/catalog references in the disposable project. Source is retained in `Tools/Presentation/author_surfaces.py`; existing stone/content art and identity mappings are preserved. No downloaded assets, package, lighting framework or per-frame texture generator.
- Compact cards use a stone footprint thumbnail beside the localized name, then a separate dimensions/base-cost row. A retained UI Toolkit mesh consumes resolved authored cells in the first allowed orientation at a shared catalog scale. No room ID/dimension special cases, texture generation or gameplay footprint authority. Outline generation also represents sparse cell sets when the existing resolver supports them. Current actual shapes are distinct; larger chambers occupy more thumbnail area. The arrow/browse hint appears only when options overflow; horizontal browsing and localized selected placement summary remain. Text/hit target sizes are unchanged. Long labels wrap rather than overlap or silently truncate; optional detail scrolling can be needed.

Only presentation/assets/localization/tests and the mobile UI vision changed. `implementation-files.txt` records exact paths. Controller changes are confined to initial overlay picking; construction builds compact previews and geometry-driven overflow hints; world view projects/ pools saved connections. The new preview class is a single retained VisualElement, not a second UI framework. Existing scene and genuine PlayMode fixtures measure layouts/input and assert connection/thumbnail representation. The vision records the owner-approved overlay/readability direction without approving entrance movement, capacity expansion or interactive doors.
