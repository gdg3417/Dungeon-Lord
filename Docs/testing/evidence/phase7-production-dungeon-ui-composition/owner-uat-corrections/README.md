## Corrections

1. Normal sheets use intrinsic content height rather than a fixed 32%. Empty construction labels are hidden; ScrollViews do not grow to consume spare space. Responsive maximums still bound optional details, while local and transaction actions remain outside those ScrollViews. Portrait and landscape retain the same bottom sheet and collapse behavior.
2. A localized **Display** button opens a compact text-size popover in Normal and Edit modes. Small, Default and Large retain the existing scaling authority and physical hit targets; no settings screen or save field was added.
3. Input System 1.17.0's installed `InputSettings.cs` documents normalized ±1 wheel units by default, versus native Windows ±120. The prior DPI divisor yielded `exp(1/160) = 1.006270` per normalized notch. Presentation configuration now owns `log(1.25)` per notch, with a separate native Windows conversion. A 0.1-unit delta yields 1.022565; one notch yields 1.25. Maximum zoom factor is 8, while MinimumViewSize remains 2: actual minimum size is `max(2, FitSize/8)`. Large deltas are bounded, mouse anchoring remains in DungeonViewport, and touch gestures retain their existing path.
4. Individual room footprints receive stone perimeter lips. The existing read-only saved-edge adapter accepts exact persisted connections before presentation exposes their transformed sockets. Optional branches reuse their existing geometry adapter. Physical contact alone creates no opening. Selected outlines preserve the same openings. Rotation and canonical tile alignment remain authoritative.
5. Room cards separate artwork, name and dedicated size/cost regions. Landscape places artwork beside text; portrait places it above. Wider cards permit horizontal browsing. Authoritative base costs and geometry still come from their existing services/catalogs; the selected preview has a localized check-mark label. Long labels wrap without overlapping art or other text.
6. Landscape HUD/header allocation and shorter, equivalent floor-summary formatting recover map height. **Fit Floor still fits the complete legal floor in Edit Mode.** Zooming automatically to occupied structures would hide legal anchors and conflict with A5 guidance semantics. This correction therefore improves the available viewport rather than inventing a cropped legal area or another camera policy. Manual pan/zoom, Focus Room and recovered out-of-bounds bounds remain supported.
7. Guidance explains that diamonds identify supported aligned doorway/straight-corridor anchors. Existing reason codes distinguish incompatible sockets, unsupported corridor lengths and geometry overlap. No routing rules changed.

All graphical assets and content mappings are retained. No simulation, occupancy, economics, schema 13, migrations, draft format, durability, atomic publication or snapshot authority changed. New English text lives in localization resources. No reserved-mana value was fabricated: the HUD still uses the current spendable wallet twice. Planning records reservation economy and A0 tap-to-connect/segment/bend editing as separate missing capabilities.

## Limits and owner retest

This is a first visual treatment, not final art or release readiness. Landscape overview intentionally retains the full legal square and therefore has unused horizontal surroundings; collapse, wheel zoom and deliberate Focus Room provide detail. Very long labels can require scrolling optional details/cards. No low-end mobile FPS or allocation claim is made.
