# Actual Unity visual checkpoint

These are runtime captures of the Bootstrap production scene, not concept art or generated target images. `CompositionVisualCheckpoint` seeds the same disposable dungeon through existing canonical APIs for the baseline and new implementation: a starter room with skeleton, spike and glittering hoard, a connected rectangle room, and a second floor. Inline funding/research is test-only. No owner save is used.

The baseline was captured from merged PR #229 at `7b5911e5482aa20851e8329c0bb311f9aa6e7206` before implementation. The baseline has no Focus Room action; its “focused” capture therefore retains its inspection camera. New captures use the explicit Focus Room action.

An additional [physical-corridor inspection](screenshots/after/composition-corridor-inspection-720x1280.png) is generated from an explicitly asserted physical connection, with selected footprint cells and read-only corridor details. It is a separate disposable fixture, not the before/after seed.

The full EditMode fixtures also produced [long invalid-placement text at 720 × 1280](screenshots/accessibility/construction-ui-invalid-long-720x1280.png), [long metric localization at 1080 × 1920](screenshots/accessibility/phase7a4-long-localization-1080x1920.png), and [Large text with safe-area insets at 1280 × 720](screenshots/accessibility/construction-layout-diagnostic-large.png). These use their existing authority-seeded regression states, separately from the comparison seed above.

The checkpoint was reviewed before full automated qualification. Corrections addressed oversized landscape controls, separate Cancel/Confirm rows, Large-text word splitting, insufficient inset map space, and initial empty-state camera framing after starter publication. Final captures show original textured paving, exposed boundary trim, distinct authored structures/content and a shared bottom sheet below the world in both orientations. The editor grid and anchor diamonds remain subordinate to the artwork; invalid footprints use X marks and localized reasons.

Optional capacity/details and text-size controls can require vertical scrolling, and placement orientation/socket choices can require horizontal scrolling. Critical confirmation and whole-dungeon actions remain outside those scroll views. This is a first art treatment: static perspective sprites, category fallbacks and simple stone trim remain visible limitations. The images do not establish final art quality or low-end mobile performance.
