## Canonical-to-final accounting design (before implementation)

The A0 Decisions 19–21 require final-state economics. Phase 4A owns construction formulas, per-structure paid investment, retired-terminal relationship carry, refunds, modifiers, rounding and wallet capacity. A5 owns normalized suffix movement contributions. Its movement-only ledger precondition and terminal-displacement check cannot accept new rooms.

Extend StructuralEconomyService rather than introducing a pricing owner. Reconcile canonical investment to final structure IDs once. Retain surviving records. Map a retired canonical terminal edge to its final successor with the same source node, using the existing direct-doorway transfer or same-definition physical-tile intersection and proportional historical investment rules. Retired remainder supplies the existing configured refund basis. Gesture history never supplies paid investment.

Each final new room is one construction formula unit. Its unit contains its configured room base and newly materialized physical corridor tiles on its incoming edge; its final outgoing completion edge also belongs to that unit if physical. Required edges between new rooms belong to the destination room. Exclude carried physical tiles. Evaluate the existing FormulaEngine once per final room, in ordinal identity order, and allocate corridor shares by the existing floor-proportional rule with the remainder assigned to the room. For a single new room this preserves the existing construction formula and investment allocation exactly. Intermediate retired draft edges have zero paid basis and no refund or charge.

Normalize movement only over canonical baseline rooms and their baseline required predecessors. New rooms have no baseline displacement or renovation basis. Where construction extends a floor, completion relocation is a construction consequence and no longer proves the baseline movement suffix. Floors without construction keep A5's exact terminal-displacement check. Price each independent existing-room target using the existing movement formula; add only its actual paid renovation cost to its retained record.

Require current usable balance to cover gross spending before refunds, matching existing structural economics. Apply the configured aggregate retirement refund/cap only after spending. Recheck current wallet, economy rules, acknowledged evidence, baseline, material identity and complete final semantic validity at Save. Publish final geometry, native ordinal allocation, wallet and investment together through the existing complete-save writer. No schema change: canonical schema remains 13.

## Draft and interaction contract

Construction adds command kind 3 with exactly one construction-intent payload: an N-format intent GUID, either one complete StructuralConstructionRequest or an explicit cancellation with no placement. Valid confirmation promotes only the authority's semantically validated candidate. Invalid confirmation retains localized reason/footprint evidence against the last valid projection; correction reuses the intent identity and cancellation removes that blocker. Completed identities cannot be reused. Transient tapping/configuration previews do not append commands, allocate canonical ordinals or spend mana.

Construction upgrades journals explicitly to format 4 and immutable candidate/commit records to version 3. Historical A4 journal 2 / record 1 and A5 journal 3 / record 2 use their exact historical DTOs and predecessor bytes. Chain upgrades 2→3→4 and 2→4 are supported; downgrades fail closed. The A5 material-input hash framing remains frozen at 3 because construction reads the same material inputs; journal and record discriminators separately bind command vocabulary. Checksums, baseline, material identity, prefix continuity and configured byte/record budgets remain enforced.

The persistent Edit category strip contains Rooms. Cards use the selected floor's real authored permitted definitions, names, footprint and configured room-base prices. Contextual controls expose every authored orientation and terminal-side option. A selected configuration gets discrete authoritative anchor guidance; a tap previews room, physical connection and relocated completion geometry plus whole-draft economics. Confirm Placement and Save Changes remain separate. Details scroll/collapse while categories and Save/Discard remain accessible. Invalid acknowledged attempts have persistent correction controls outside collapsed details.

Bootstrap normal-player structural construction and legacy append controls are retired behind the existing diagnostics visibility policy. Legacy starter setup remains available for a virgin canonical save with no floor records and for empty active Floor 1. StructuralEditService requires an existing required-route room tail on an active floor; its distinct first-room case explicitly requires an existing inactive floor with no rooms or edges. Production's new-save experience does not already supply that tail. The focused starter-boundary test and production append scene tests distinguish these cases. Ordinary players with an established tail can select, preview, confirm, recover and save subsequent construction entirely in production Dungeon Edit Mode. A fresh player still needs the legacy starter action. The owner explicitly accepted this PR-specific limitation on October 8, 2026; fresh-game graphical setup parity is not claimed or silently implemented. Reassess this outstanding onboarding capability during later Phase 7 planning. Replacement, deletion, lifecycle, branches, content acquisition/custody, Research and Run/Observe remain unmigrated.

Focus Room is deferred to the dedicated UI composition/room-content work: the vision's inspect-only Normal selection and focus require coordinated selection/input lifetime behavior. This PR preserves A5 room selection/movement and Focus Floor without extending Normal interaction ownership.
