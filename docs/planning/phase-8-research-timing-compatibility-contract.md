## 3. Why schema 17 falls short

Two otherwise identical zero-progress projects started at logical 2 s and 7 s can both be saved at C=A=8 s. Their pending IDs, source label, progress, latch, total ticks and current accounted wall boundary can agree. Their next credits must be 8 s and 3 s respectively. The current horizon tells when the save is closed, not when the action occurred. A negative initial progress balance contradicts validation. Treating the label as a free-form encoding of time would make each Start a different rule identity and an old reader could still apply the bootstrap terms.

|Option|Disposition|
|---|---|
|A. Validate a versioned reference only, retain schema 17|Resolves rule selection only. Cannot distinguish the two cuts. Reinterpreting the old double or label in place also admits a schema-17 writer that understands neither new meaning.|
|B. Schema 18, discriminate paid and legacy progress, add one cut|Recommended. A distinct semantic rule reference fits the existing source-ID member for new starts only. One scalar records the missing observation. Existing slot, wallet, progress, readiness, completed IDs and scheduler already cover the other facts.|
|C. New H1 context version|Unnecessary for this slice. Replay of the paid branch depends on frozen input bytes identified by the project's own content-addressed reference plus the same twelve H1 inputs. Extending the global digest alone would still leave both the original Start and per-project version unresolved.|

## 4. Proposed immutable registry and wire contract

Use an append-only release archive of canonical rule bytes, with a separate project-to-current-reference selection for **new Start only**. A rule family is `research.timing.<slug>` where slug matches ASCII `[a-z][a-z0-9_]{0,31}`. A release key is family plus `.v<N>` where N is a positive canonical decimal Int32. The saved reference is the release key plus `.` and the 64 lowercase hex characters of SHA-256 over the exact retained rule bytes. Example family and first release key are `research.timing.adventurer_analysis.v1`. The digest is computed after authoring. Do not hash a reserialized Unity object.

Proposed rule format 1 is compact UTF-8 JSON, no BOM or trailing newline, fields in order: `formatVersion` (1), `releaseKey`, `projectId`, `slotId`, `manaCost`, `requiredEligibleSeconds`. Use canonical positive whole decimals for this starter contract, exact wallet-representable cost, positive duration whose checked product with bound units/second is at most 2^53−1. Validate canonical bytes by parsing and round-trip. Format 1 fixes eligible foreground scheduler units, one unit credit per eligible unit, tick-end evaluation, saturation at threshold and ordinary local claim gates. A change in cost, duration, binding or eligibility semantics requires a new release key (and a new supported format for changed semantics). No independently tunable normalized rate. Track the released key-to-hash map across builds and reject replacement, reuse or deletion of a needed historical entry. Resolve against actual validated bytes, retaining an immutable parsed snapshot for a session.

Require exactly one unambiguous enabled selection per offered project, matching released key, hash, project and slot. Disabling new starts changes selection only. Archived entries remain readable even if retired. Reject duplicate keys (even with different hashes), duplicate selections, missing fields, case aliases, overflow, unknown formats, conflicting bindings and hash mismatches. Fail the affected Start if no enabled selection exists. An absent historical dependency blocks opening/writing an affected active save. A newer default never participates in that decision. #271's proposed price-only format has schemaVersion, enabled, projectId, progressRuleId, completionRuleId and manaCost. Adapt its affordability consumer to this one rule source when integrating, preserving its missing-config refusal. Do not import its implementation into the prerequisite. General and Blueprint can use the same binding and resolver later. No second slot is allocated here.

**Save grammar.** Keep root and primary member order and recognized nulls. `researchPending` retains its two IDs. For a newly started paid project, recognized `researchProgress` members in canonical order are `SlotId, ProjectId, ProgressUnits, CompletionPending, RuleSourceIdUsed, StartClosedThrough`. Append the last member as an unquoted canonical nonnegative Int64 (no sign, leading zero, fraction or exponent). Require both a valid paid reference and this member. A legacy progress object retains the original five recognized members and the exact historical source label from the matched bootstrap, with no cut. An absent progress object stays absent/null according to the frozen source rules. A cut without a paid reference, a paid reference without a cut, ambiguous new-member collision or a synthetic empty object cannot authorize a paid project. Never infer variant from elapsed amount, price, wall date or whether the latch is set.

For paid rows `ProgressUnits` is an exact whole number in [0,D] where D is duration in scheduler units. Parse/check exact integrality in the canonical node before conversion to a double, and prove value-preserving readback. Use checked integer arithmetic internally. Keep legacy doubles and comparison order verbatim, including their actual rounding. Expose elapsed/required seconds as derived views to the paid presentation. Do not persist a second normalized fraction. Validate C≥S≥0, initialized scheduler, matching project/slot, paid latch iff progress=D, unique occupancy and absence from completed IDs. For this foreground-only version require progress to equal min(D, max(0, floor(C/W)×W−S)) at a **published closed boundary** (C may be less than A), with W the bound tick width. The executor currently reopens validated private sessions at passive, settlement and release substages before updating C. Compute the paid Research result at passive-tick order and retain that result locally for this boundary. Materialize it in the recognized progress record at the final closure Stage after setting C, across any intervening projection replacements. No party or opportunity branch consumes paid Research readiness. Discard the local result on failure. This allows the same equation on every byte image without weakening ordinary open validation. Legacy records cannot satisfy this equation because their cut is unknown.

## 5. H1 identity and schema activation

Reconstruct from the authorized consumed bytes and validate their interpretation, including mutable DTO guards. Compare against the saved identity even for closed saves. The hash in a save supplies no inputs. The special historical compatibility exception in `SupportsHistorical` concerns schema-17 registration in input 10 during 16→17 activation. ## 6. Start, evaluation order and proof of credit

1. Use the existing foreground action barrier. Capture the authoritative observation, drain earlier accepted work to the action cut under its predecessor state, and refresh the live projection. If a bounded flush needs another pump, return boundary-pending and stage nothing. Require a proven, current, closed, initialized scheduler, an eligible foreground action context, and no pending writer, deferred absence, unresolved recovery or uncertainty. Active parties are permitted. A prior terminal settlement may satisfy the prerequisite only once closed.
2. In `CommitPlayerResearchTransition`, recheck those conditions against the exact predecessor, including stable observation classification at adoption. Read **S = actual ClosedThrough = AcceptedThrough** after the flush, including any later boundary actually closed while draining. Initialize dormant scheduler through the normal pump first. Do not read the click time, wall time, transient free-running sample or a stale UI cut. A Start is ordered immediately after all same-cut effects. Re-evaluate eligibility, occupied/completed status and spend against this detached candidate. Atomically publish the debit, S, selected reference, IDs, zero earned and false latch. S is the logical linearization point conditional on proven publication. Disk acknowledgement latency is not an additional elapsed input.
3. When the existing executor selects `time == nextTick`, pass its actual logical due time T and bound width W to Research alongside the existing tick index for other passive consumers. For paid work at this tick, credit `max(0, T − max(S, T−W))` units. Add up to remaining D, latch at D, stop increasing once ready. Use checked arithmetic. A tick already closed at Start is never replayed. Non-tick action, party-event and partial closure boundaries do not independently award Research. In particular use T−W, **not the previous pump's C**: intermediate closures could otherwise erase earned fractions.
4. Retain same-time order: passive tick (Research then passive mana), party execution/terminal settlement, recovery and waiting transfers, opportunity/admission and same-time newborn work, then closure. The writer may stage intermediate states privately. Jointly publish all completed effects and their closure. Tick errors must abort the whole candidate; the existing ignored return from `ApplyActiveTick` cannot authorize a successful closure with missing credit. A Start at a due time follows closure of that tick.
5. For paid format 1 every unit of **accepted eligible foreground** after S qualifies, including time with a party running or later insufficient usable mana. TimeService's focus/pause, recovery and publication-stall rules determine what enters logical time. Suspended wall intervals and H1 original/residual absence grants add zero Research. Resume with the same A/C machinery. A future offline feature needs its own reviewed eligibility transition within H1's exactly-once settlement, plus a successor rule/validation equation; it can apply earned duration to this same project without another clock.
6. Reopen uses saved S and earned units. Draining A>C can close only previously unclosed tick boundaries. The candidate's exact predecessor and joint publication of C and effects prevent duplicate credit. A failed Start publishes no logical S on the predecessor. A proven successor contains all Start effects once. After a successful Start a later failed tick leaves the last proven Start/progress intact, or requires exact outcome recovery before retry. Only the intersection strictly after S can contribute, regardless of how much earlier work was accepted or how long storage took.

## 8. Failure contract and qualification matrix

Proposed deterministic diagnostics: `research.timing.rule_invalid` for malformed reference/registry, duplicate or contradictory content, `research.timing.rule_missing` for a well-formed unavailable archive key, `research.timing.rule_mismatch` for wrong digest or binding, `research.timing.start_disabled` for unavailable new selection, `research.timing.state_invalid` for wire, cut, accumulator or latch inconsistency, `research.timing.legacy_unproven` for an unprovable legacy mapping. Precedence: validate frozen envelope/context first, parse shape and reference, resolve archive, verify bytes/binding, then validate state. Apply enablement only at Start. Map diagnostics to stable localized player feedback. Reuse existing prerequisite/occupied/claim feedback, foreground boundary, storage, H1 context and historical-proof reasons. Validation is side-effect-free. No error pays, repairs a record, advances time or acknowledges an action.
